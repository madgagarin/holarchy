# Справочник по API Оркестратора

Этот документ описывает все HTTP-эндпоинты, предоставляемые сервером Оркестратора. API разделен на три логические группы: Публичные, Клиентские и Внутренние (для Воркеров).

## Аутентификация

- **Клиент -> Оркестратор:** Все запросы к клиентским эндпоинтам (префикс по умолчанию `/api/v1/*`) должны содержать заголовок `X-Client-Token` с токеном клиента. Часть пути `/api` настраивается через `CLIENT_API_PREFIX`.
- **Воркер -> Оркестратор:** Все запросы к эндпоинтам `/_worker/*` должны содержать заголовок `X-Worker-Token` с валидным токеном воркера.

---

## 1. Публичные эндпоинты (`/_public`)

Эти эндпоинты не требуют аутентификации и всегда используют фиксированный префикс `/_public`.

### Проверка статуса сервиса

- **Эндпоинт:** `GET /_public/status`
- **Описание:** Подтверждает работоспособность сервиса.
- **Ответ (`200 OK`):** `{"status": "ok"}`

### Вебхук ручного подтверждения (Human Approval)

- **Эндпоинт:** `POST /_public/webhooks/approval/{job_id}`
- **Описание:** Позволяет внешней системе или оператору подтвердить, отклонить или направить выполнение шага пайплайна, находящегося в состоянии `waiting_for_human`.
- **Аутентификация и безопасность:**
  - **Одноразовый Scoped Approval Token:** Ограниченный по времени криптографический токен, генерируемый при переходе задачи в статус `waiting_for_human`. Может передаваться в query-параметре URL (`?token=<approval_token>`) или в JSON-теле запроса (`{"token": "<approval_token>", ...}`). После первого успешного использования токен немедленно аннулируется для защиты от replay-атак.
  - **Fallback-авторизация по Client Token:** Если токен подтверждения не передан, запрос обязан содержать валидный заголовок `X-Client-Token` владельца задания. При отсутствии корректной авторизации возвращается `401 Unauthorized`.
- **Тело запроса:**
  ```json
  {
    "decision": "approved",
    "token": "опциональный_токен_если_не_передан_в_query"
  }
  ```
  - `decision` (string, обязательный): Решение по шагу, соответствующее разрешенным веткам перехода (например, `"approved"`, `"rejected"`).
  - `token` (string, опциональный): Одноразовый токен подтверждения (если не передан в строке URL).
- **Коды ответов:**
  - `200 OK`: `{"status": "approval_received", "job_id": "..."}`
  - `400 Bad Request`: Пустое тело, некорректный JSON или отсутствует поле `decision`.
  - `401 Unauthorized`: Не передан/недействителен `approval_token` и отсутствует корректный `X-Client-Token`.
### Интерактивная документация API

- **Эндпоинт:** `GET /docs` (или `GET /_public/docs`)
- **Описание:** Возвращает брендированную интерактивную HTML-страницу документации API с возможностью отправки тестовых запросов, инспектором 5 зон хранения и бейджами уровней риска и разрешений.
- **Ответ (`200 OK`):** HTML-страница (`text/html`).

### Динамическая спецификация OpenAPI 3.1.0

- **Эндпоинт:** `GET /openapi.json` (или `GET /_public/openapi.json`)
- **Описание:** Динамически генерирует полную спецификацию OpenAPI 3.1.0, включающую все зарегистрированные блупринты, пространственные DAG, эндпоинты каталога навыков и заголовки оркестратора.
- **Ответ (`200 OK`):** JSON-объект (`application/json`) по стандарту OpenAPI 3.1.0.

## 2. Клиентские эндпоинты (`/{CLIENT_API_PREFIX}/v1`)

Предназначены для внешних систем, инициирующих и контролирующих рабочие процессы. Требуют заголовок `X-Client-Token`.
Базовый путь для этих эндпоинтов настраивается через переменную окружения `CLIENT_API_PREFIX` (по умолчанию `api`). Если установить пустую строку, эндпоинты будут доступны от корня (например, `/v1/...`).

### Заголовки запроса к Оркестратору

При создании заданий параметры управления оркестрацией передаются через стандартные HTTP-заголовки, сохраняя тело запроса чистым для доменных данных:

- `X-Client-Token` (string, обязательный): Токен аутентификации клиента.
- `X-Job-Priority` (string, опциональный): Приоритет выполнения (`critical`, `high`, `normal` [по умолчанию], `low`, `background`).
- `X-Job-Timeout` (integer, опциональный): Максимальное время выполнения задания в секундах.
- `X-Correlation-ID` (string, опциональный): Идентификатор сквозной трассировки, передаваемый по всем шагам и воркерам.
- `Idempotency-Key` (string, опциональный): Ключ идемпотентности, исключающий повторный запуск задания при сетевых сбоях и ретраях.
- `X-Webhook-URL` (string, опциональный): URL вебхука для асинхронного уведомления о переходе задачи в финальный статус.

### Создание нового задания (Пользовательский эндпоинт блупринта)

- **Эндпоинт:** `POST /{CLIENT_API_PREFIX}/v1/{blueprint_api_endpoint}`
- **Пример:** `POST /api/v1/jobs/orders`
- **Описание:** Запуск нового экземпляра (Job) через персональный путь, заданный в декораторе блупринта.
- **Заголовки:** См. «Заголовки запроса к Оркестратору» выше.
- **Тело запроса:** Чистые доменные входные данные, соответствующие схеме стартового шага блупринта:
  ```json
  {
    "order_id": 42,
    "amount": 150.0,
    "is_vip": true
  }
  ```
- **Ответ (`202 Accepted`):**
  ```json
  {
    "status": "accepted",
    "job_id": "123e4567-e89b-12d3-a456-426614174000"
  }
  ```

### Создание нового задания (Универсальный стартер)

- **Эндпоинт:** `POST /{CLIENT_API_PREFIX}/v1/jobs/start/{blueprint_name}`
- **Пример:** `POST /api/v1/jobs/start/ecommerce_orders`
- **Описание:** Универсальный эндпоинт для запуска любого зарегистрированного блупринта по его имени (даже без выделенного пути).
- **Заголовки:** См. «Заголовки запроса к Оркестратору» выше.
- **Тело запроса:** Чистые доменные входные данные блупринта.
- **Ответ (`202 Accepted`):**
  ```json
  {
    "status": "accepted",
    "job_id": "123e4567-e89b-12d3-a456-426614174000"
  }
  ```
- **Ответ (`404 Not Found`):** Блупринт с указанным именем не зарегистрирован.

### Получение статуса задания

- **Эндпоинт:** `GET /api/v1/jobs/{job_id}`
- **Описание:** Возвращает текущее состояние задания, структурированное по 5 изолированным зонам хранения (`input`, `output`, `meta`, `artifacts`, `receipts`).

#### Статусы заданий (Job Statuses)

Система использует следующие статусы для управления жизненным циклом заданий:

**Промежуточные состояния:**

- `pending`: Задание создано и ожидает постановки в очередь выполнения.
- `running`: Задание активно обрабатывается.
- `waiting_for_worker`: Ожидание освобождения или подключения подходящего воркера.
- `waiting_for_human`: Ожидание действия или подтверждения от человека (Human-in-the-loop).
- `waiting_for_parallel`: Ожидание завершения всех подзадач в параллельной ветке.

**Финальные состояния (Terminal States):**

- `finished`: Задание успешно завершено. Финальный результат доступен в зоне `output`.
- `failed`: Ошибка в логике или на стороне воркера. Детали ошибки доступны в ответе.
- `cancelled`: Задание отменено пользователем или системой.
- `error`: Критическая системная ошибка при выполнении.
- `quarantined`: Задание помещено в карантин для ручного разбора (например, при нарушении контракта схемы или сбое воркера).

* **Параметры:** `?fields=status,output` — фильтрация возвращаемых полей.

**Примечание по безопасности:** Поле `output` заполняется и становится доступным только тогда, когда задача достигает финального успешного состояния (`finished`). Для задач в промежуточных состояниях результат скрыт для защиты промежуточных данных.

**Изоляция данных:** Доступ к задаче строго ограничен клиентом, который её создал. Вы должны предоставить тот же `X-Client-Token`, который использовался при запуске. Любая попытка доступа к ID задачи другого клиента вернет `404 Not Found` (в целях безопасности, чтобы предотвратить перебор ID).

**Компактный ответ (по умолчанию):**

```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "status": "finished",
  "blueprint_name": "ecommerce_orders",
  "current_state": "FlowStates:finalize"
}
```

**Детальный ответ (структура 5 зон хранения):**

### Диагностическая карточка инцидента (Evidence Card)

- **Эндпоинт:** `GET /api/v1/jobs/{job_id}/evidence`
- **Описание:** Генерирует исчерпывающую диагностическую карточку для заданий в статусе `failed` или `quarantined`. Незаменима для постмортемов и автоматического устранения инцидентов.
- **Параметры:**
  - `format` (string, опциональный): Формат ответа — `json` (по умолчанию) или `md` (Markdown).
- **JSON-ответ (`200 OK`):**
  ```json
  {
    "job_id": "123e4567-e89b-12d3-a456-426614174000",
    "blueprint_name": "ecommerce_orders",
    "status": "quarantined",
    "failed_step": "FlowStates:charge_card",
    "error_message": "Payment gateway timeout after 3 retries",
    "remediation": "Check gateway API availability or replay job via /jobs/start/ecommerce_orders.",
    "receipts": [...]
  }
  ```
- **Markdown-ответ (`200 OK` при `?format=md`):** Форматированный документ (`text/markdown; charset=utf-8`), готовый к отправке в Slack, Jira или GitHub Issues.

### Работа с S3

- `GET /api/v1/jobs/{job_id}/files/upload` — получение presigned ссылки для загрузки.
- `PUT /api/v1/jobs/{job_id}/files/content/{filename}` — прямой стриминг файла через прокси оркестратора.
- `GET /api/v1/jobs/{job_id}/files/download/{filename}` — стабильная ссылка на скачивание.

### Управление, визуализация и диагностика

- `POST /api/v1/jobs/{job_id}/cancel` — отмена активной задачи.
- `GET /api/v1/jobs/{job_id}/history` — полная история событий задания. В компактном режиме снимки состояния (`context_snapshot`) внутри событий фильтруются.
- `GET /api/v1/blueprints/{blueprint_name}/graph` — структура блупринта в формате Graphviz DOT.
- `GET /api/v1/blueprints/{blueprint_name}/dag` — пространственная 2D-топология DAG графа с координатами узлов, типами шагов (`start`, `step`, `decide`, `parallel`, `human`, `end`), ветками переходов, уровнями риска и списком разрешений.
- `GET /api/v1/workers` — список всех активных подключенных воркеров.
- `GET /api/v1/dashboard` — агрегированная статистика состояния системы, очередей и задач.
- `GET /api/v1/skills` — каталог зарегистрированных навыков воркеров в кластере (кэш 10 сек).
- `GET /api/v1/skills/{skill_name}` — детальная спецификация и контракт конкретного навыка (`input_schema`, `output_schema`, `risk`, `permissions`).
- `GET /api/v1/jobs` — список всех задач. В компактном режиме снимки состояния фильтруются.
- `GET /api/v1/jobs/quarantined` — список задач, находящихся в карантине для ручного разбора.

## 3. Внутренние эндпоинты для Воркеров (`/_worker`)

Требуют заголовок `X-Worker-Token`.

### Регистрация и Heartbeat

- **POST /\_worker/workers/register** — регистрация воркера и его возможностей.
- **PATCH /\_worker/workers/{worker_id}** — подтверждение активности (Heartbeat). Возвращает `next_heartbeat_jitter_ms`.

### Задачи и результаты

- **GET /\_worker/workers/{worker_id}/tasks/next** — получение новой задачи (Long-Polling + Work Stealing).
- **POST /\_worker/tasks/result** — отправка результата выполнения задачи.
- **POST /\_worker/events** — отправка промежуточного события (прогресс, логи).

### WebSocket

- **GET /\_worker/ws/{worker_id}** — канал для команд реального времени (например, `cancel_task`).
